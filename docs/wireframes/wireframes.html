Annotations

  • Every field has a persistent visible label, not placeholder-only text (Slide 18 — ask only what's needed, right keyboard type, keep input intact).
  • Inline error sits directly under the field it belongs to, in plain language, no stack trace (Slide 19 — error messages that help).
  • Offline: fields stay filled and a "draft saved" indicator appears — nothing is lost if the app is killed (Slide 20 — offline states preserve confidence).
  • Claim code links this registration to a record the lecturer may have pre-entered, preventing duplicate profiles (brief requirement, not a slide principle).
  • Touch targets ≥ 48dp; buttons full-width for easy reach (Slide 17 — touch targets and thumb zones).

Annotations

  • One sign-in form for both roles; role comes from the account, not a picker (reduces user error; brief requirement).
  • Session token stored securely; never stores raw password on device (security requirement, not a Unit 2 UI slide).
  • Focus order: field 1 → field 2 → button, verified with TalkBack (Slide 31 — screen reader friendly design, focus order follows visual/task order).
  • Error state (wrong credentials) reuses the same inline-error pattern as registration for consistency (Slide 19 — error messages that help).

Annotations

  • Student number field is visibly locked (icon + muted style) — only lecturers can change it, protecting identity (brief requirement).
  • Group occupancy shown live (12/15) so the student understands capacity before requesting a change (Slide 30 — accessibility is not optional, clear labelling supports all users).
  • Status labels ("Pending", "Synced") are text, not colour-only, for colour-blind and low-contrast users (Slide 30 — accessibility supports visual limitations and temporary conditions like glare).

  • Group dropdown shows live occupancy next to each option; a full group (15/15) is shown but disabled with a reason (Slide 19 — errors explain what happened, not just that it failed).
  • Delete opens a confirm dialog ("This will free their place in G02 — Cancel / Delete") before anything happens (Slide 15 — back behaviour and user trust, confirm when loss is possible; Slide 16 — don't make destructive actions easy to trigger accidentally).

6. Sync & error states

Annotations

  • Every sync state is a text label plus icon — never colour alone — and announced to TalkBack when it changes (Slide 20 — offline/loading states are part of UX, not decoration; Slide 31 — screen reader friendly design).
  • "Action required" opens a compare view: your proposed edit vs. the current server record, so nothing is silently overwritten (Slide 19 — error messages explain how the user can recover).
  • Manual "Sync now" always available, on top of automatic WorkManager retries (Slide 20 — loading states should reassure users that work is progressing).
